# AGENTS.md — sbe-web («LogicTEAM.WWW»)

Веб-портал SBE — единственный клиент в проекте, который не является Obsidian-плагином
(нет `manifest.json`, никогда не грузится в Obsidian). По аналогии с `mobile/`
(мобильные плагины живут вне `.obsidian/plugins`) — исходники в
`C:\Obsidian\mailers\web\sbe-web\`, собранный `dist/` копируется на сервер вручную
(`scp`), без CI. Design: `docs/superpowers/specs/2026-09-02-sbe-web-portal-design.md`
(в репозитории `sbe-core`).

## Назначение

- **Вход** — magic-link: email → письмо со ссылкой (5 мин, одноразовая) →
  `POST /auth/web/consume` → `{key, device_id}` в `localStorage` (бессрочно, как у
  Obsidian-плагина, до ручного отзыва через `/auth/devices`). Дальше — обычный
  `POST /auth/token {key, app_id}` (то же самое, что `sbe-apstore.auth.getToken`
  для плагинов).
- **Фотобанк** (`/photobank`) — только просмотр/поиск/соцслой (лайк, избранное,
  комментарии, скачивание оригинала). Загрузка/редактирование/управление папками —
  только через Obsidian-плагин: сервер блокирует запись для JWT с `channel=web`
  независимо от роли (см. `sbe-photobank/photo-service/AGENTS.md`).
- **Заявки на испытания** (`/requests`) — зеркало admin-уровня плагина
  `sbe-requests`: заявки, проекты (+ триггеры почты, смена родителя), группы,
  права доступа. `superadmin` недостижим через веб ни при каких обстоятельствах —
  сервер клэмпит эффективную роль `superadmin → admin` для `channel=web`
  (см. `sbe-lims/lab-service/AGENTS.md`).

## Структура

| Путь | Что это |
|---|---|
| `src/api/http.ts` | Общий fetch-слой: таймаут, `ApiError`, единая обработка 401/403 |
| `src/api/authApi.ts` | `requestLink`/`consumeLink`/`getToken` (кэш JWT в памяти на `app_id`) |
| `src/api/photoApi.ts` | Клиент photo-service (только используемые read+social эндпоинты) |
| `src/api/labApi.ts` | Клиент lab-service (requests/projects/objects/groups/permissions/files/protocol) |
| `src/api/llmApi.ts` | Клиент llm-service: ключ провайдера пользователя (`getStatus`/`setApiKey`/`deleteApiKey`, `SettingsView`), `listModels`/`complete`/`completeJson` (порт `SbeLlmApi`, для agent-модуля) |
| `src/api/agentApi.ts` | Клиент agent-service: файлы (generate/parse), данные (mailer/documents/contacts/lab/photo pull, всегда напрямую), скилы (только глобальные), история диалогов, правила, системный промпт, скретч-хранилище (S3, 48ч) |
| `src/store/session.ts` | Сессия (`{key, device_id, email}`) в `localStorage`, реактивное состояние |
| `src/router.ts` | Hash-роутинг (`createWebHashHistory`) — magic-link `#/verify?token=...` |
| `src/views/` | `LoginView`/`VerifyView`/`LauncherView`/`SettingsView` (ключ ИИ) |
| `src/modules/photobank/` | `PhotobankView` + `FolderTree`/`PhotoThumb`/`PhotoDetailModal` |
| `src/modules/requests/` | `RequestsView` + `ProjectTree`/`ProjectsPanel`/`RequestDetail`/`RequestCreateModal`/`GroupsPanel`/`PermissionsPanel` |
| `src/modules/agent/` | `AgentView` (чат LogicTEAM.007) + `agentEngine.ts` (цикл LLM↔тулы, порт sbe-agent) + `tools.ts` (реестр тулов) + `systemPrompt.ts` |

## Правила

- Обычный `fetch()` — не `requestUrl()` (это Obsidian API, здесь не нужен и недоступен).
- `catch` — по возможности `unknown` + `errorMessage()` (см. `src/api/http.ts`), без `any`.
- UI на русском; автор — Полищук Евгений (polishchuk@tn.ru).
- Классы `sw-*` на CSS-переменных (`src/style.css`) — свой набор токенов, не
  завязан на `sbe-core` (это не Obsidian-плагин).
- `vite.config.ts`: `base: '/app/'` — обязателен, иначе собранные ассеты будут
  ссылаться на корень домена вместо `/app/`.
- Коммиты/пуши — только по явной команде пользователя («Фиксируй»).

### 2026-09-06 — v0.1.12 (защита от раздувания контекста диалога агента)

Дизайн: `docs/superpowers/specs/2026-09-06-web-agent-context-compaction-design.md`.
Продолжение разбора инцидента 504 из v0.1.11 — там точечно чинили ЮГайл, здесь
закрывается сам системный механизм, а не конкретный тул.

- **Отказ вместо обрезки**: `summaryForLlm` (`agentEngine.ts`) при превышении
  результатом тула `MAX_TOOL_DATA_CHARS` (30000 символов, порог не менялся)
  больше не режет JSON посередине — модель получает честное «данные слишком
  большие (N символов, лимит 30000) — не показаны, уточни фильтр/лимит или
  используй агрегирующий тул».
- **Сжатие истории диалога**: новый `compactHistoryIfNeeded()`, вызывается в
  начале `run()` до сборки транскрипта. Триггер — суммарная длина
  `dialog.messages` больше `HISTORY_COMPACT_THRESHOLD_CHARS` (50000 символов).
  Последние `HISTORY_KEEP_RECENT` (8) сообщений остаются как есть, всё
  старше — один дополнительный LLM-вызов с отдельным промптом
  (`COMPACTION_SYSTEM_PROMPT`), обязательно сохраняющим числа/id/даты/решения
  в структурированном виде; если в начале «старой части» уже есть дайджест
  прошлого сжатия — промпт явно просит его ОБНОВИТЬ, а не сжать заново (иначе
  при повторных циклах терялись бы более старые факты). Результат заменяет
  `dialog.messages` на `[{role:'summary', digest}, ...последние 8]` и сразу
  сохраняется (`agentApi.saveDialog`). Сбой сжатия (ошибка LLM) — тихо
  пропускается, обычный ответ не блокируется.
- Новая роль сообщения `summary` (`types/agent.ts`) — в `serializeHistory()`
  как `[Свёрнутая история] ...`, в `AgentView.vue`/`style.css` — отдельный
  приглушённый блок (`.sw-agent-msg--summary`, пунктирная рамка), не обычная
  реплика ассистента.
- Только веб-агент — Obsidian-плагин `sbe-agent` не менялся (перенос отложен).

### 2026-09-06 — v0.1.9 (LogicTEAM.007: график без ручного mermaid; стоп по Esc)

несколько раз пересоздал один и тот же PNG-график (`create_mermaid`) и не

**Диагноз (два независимых механизма, оба нужно было починить)**:
1. Реальная причина падения графика (`render error`) — в логах `agent-service`
   (`docker logs agent`) нашёлся parse error `mmdc`: модель дописала в код
   `xychart-beta` несуществующий оператор `legend` (такого узла нет в этой
   грамматике mermaid). HTTP-ответ сервера отдаёт только общее `render error`
   (`agent-service/files.go:167` логирует полный текст, наружу — нет) — по
   одному сообщению агента причину было не понять.
2. Зацикливание НЕ ловил анти-цикл-гард `agentEngine.ts` — его ключ
   `тул:JSON.stringify(аргументов)` требует БУКВАЛЬНО одинаковых аргументов
   3 раза подряд, а модель каждый раз чуть меняла код/заголовок — формально
   «разные» вызовы. Глубже: движок (проверено — то же в Obsidian-версии
   `sbe-agent/src/agent/agent-engine.ts`, не баг веба) добавляет в транскрипт
   только РЕЗУЛЬТАТЫ тулов, а не сам `tool_call`, который написала модель —
   на следующей итерации модель не видит свой предыдущий mermaid-код, не
   может ни проверить его, ни точечно поправить подписи оси X, и генерирует
   график заново вслепую. **Это отдельный архитектурный разрыв, не закрыт
   в этой сессии** — см. «Проблемные вопросы» ниже.

**Фикс 1 — график без ручного mermaid-кода** (закрывает конкретный повод для
зацикливания, не сам механизм): `create_png` теперь принимает `chart.
categories`+`chart.series` (несколько именованных рядов на общих датах,
например «поступление»/«завершение» из `data.series` у `get_lims_requests
group_by=...`) — backend (`agent-service/mermaid.go`, см. его AGENTS.md)
сам собирает код `xychart-beta` из чисел, модель никогда не пишет
mermaid-синтаксис для такого графика и не может ошибиться в нём (нет
`legend`, нечего галлюцинировать). `create_mermaid` теперь явно предупреждает
не использовать его для числовых графиков и напоминает про прошлую ошибку
с `legend`. Правка «покажи только день» — это теперь одна правка массива
`categories` в новом вызове `create_png`, а не пересборка всего графика.

**Фикс 2 — стоп по Esc**: `AbortSignal` протянут через весь путь одного шага
цикла — `http.ts` (`RequestOptions.signal`, объединяется с внутренним
таймаутом) → `llmApi.ts` (`retryWithBackoff`/`abortableSleep` — прерывает и
паузу между ретраями, не только сам запрос) → `AgentEngine.stop()` (новый
публичный метод, проверка `signal.aborted` в начале каждой итерации и после
каждого хода). `AgentView.vue`: активный `AgentEngine` — в `ref`, слушатель
`keydown Escape` пока идёт отправка + видимая кнопка «⏹ Стоп (Esc)» рядом с
индикатором «Агент думает…».
- **Известное ограничение**: сигнал прерывает ожидание ответа LLM (самое
  долгое звено — до 180с + ретраи), но НЕ уже начатое исполнение тула
  (например, если файл уже генерируется на сервере) — это отдельная, более
  глубокая протяжка сигнала через каждый тул, не сделана.

## Проблемные вопросы (не закрыты, требуют отдельного решения)

- **Движок не помнит свои же вызовы тулов внутри одного цикла.** `agentEngine.
  ts` кладёт в транскрипт только результаты тулов, а не сам `tool_call`
  (аргументы), который сформировала модель — на следующей итерации модель не
  видит, что именно она только что сгенерировала (mermaid-код, JSON-спеку
  документа и т.п.), и не может ни сверить, ни точечно доработать свой же
  результат, только пересоздать с нуля. Тот же паттерн в Obsidian-плагине
  `sbe-agent` — не специфично для веба. Настоящий фикс — эхо `tool_call` в
  транскрипт (с учётом токен-бюджета для длинных `code`/`spec`), не сделан.
- **Анти-цикл-гард сравнивает аргументы буквально.** Ключ `тул:JSON.
  stringify(аргументы)` не ловит «почти одинаковый» повторный вызов
  content-генерирующих тулов (`create_docx/xlsx/pdf/json/mermaid/png/html`) —
  из-за пункта выше модель может менять несущественные детали (заголовок,
  форматирование) между попытками и уходить в цикл, невидимый гарду. Возможное
  направление — отдельный (более мягкий) лимит вызовов на любой `create_*`
  тул за один `run()`, независимо от точного совпадения аргументов.
- **`create_png` с `categories`/`series` есть только в веб-агенте.** Обсidian-
  плагин `sbe-agent` (`tools-registry.ts`) использует старую схему `create_png`
  (один ряд `data`) — бэкенд уже готов принять оба формата, но схему тула для
  Obsidian-клиента никто не обновил. Сделать отдельной задачей, если та же
  потребность (график с несколькими рядами) всплывёт в Obsidian-версии.
- **Esc не прерывает уже выполняющийся тул**, только ожидание ответа LLM (см.
  «известное ограничение» выше) — если понадобится честная отмена и файловых
  генераций/долгих HTTP-вызовов тулов, нужно протянуть `AbortSignal` в каждый
  `AgentTool.execute`, отдельная работа.
